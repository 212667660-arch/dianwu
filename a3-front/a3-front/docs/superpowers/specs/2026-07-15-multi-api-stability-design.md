# A3 多 API 高可用、模型与推理强度设计

> 日期：2026-07-15  
> 任务：S-017  
> 状态：用户已授权采纳  
> 核心原则：稳定性第一，安全边界不退让，速度优化必须有测量依据

## 1. 背景

当前桌面版只保存一套模型配置。Electron 使用 `safeStorage` 保存密钥，启动后把单一配置注入 Python 后端；配置变更需要重启后端。该方案已经能稳定连接当前 DeepSeek OpenAI 兼容网关，但无法满足以下需求：

- 保存并随时切换多套 API 配置；
- 主配置故障时自动切换备用配置；
- 按学习空间选择模型和推理强度；
- 在不泄露密钥、不混合流式输出的前提下提高可用性；
- 为未来更多模型供应商、桌宠和插件能力保留明确扩展边界。

T-034 的真实基线为 11/11 次调用成功。后端连续调用 P50 为 1329 ms、P95 为 2108 ms；桌面完整链路为 1429–1947 ms。当前没有证据支持激进调整超时、并发或连接池，因此本设计把优化重点放在配置热切换、连接复用、受控重试和故障隔离，而不是牺牲稳定性换取表面速度。

## 2. 目标与非目标

### 2.1 目标

1. Electron 加密保存多套配置，renderer 永远不能读取完整 API Key。
2. 用户可指定全局默认配置，并在每个学习空间中覆盖配置、模型和推理强度。
3. 后端在内存中维护配置快照、客户端连接池、健康状态和熔断状态，不把密钥写入数据库或日志。
4. 配置可原子热应用，不因普通切换而重启整个后端。
5. 自动故障转移只处理明确可重试错误，并有总尝试次数与总截止时间边界。
6. 不同供应商的推理能力通过适配器映射；不支持的参数不发送，并向界面返回实际生效档位。
7. 保持现有单配置数据和接口的向后迁移能力。

### 2.2 非目标

- 不实现账号云同步或跨设备同步；
- 不把多 API 当作负载均衡池，不做轮询分流；
- 不做精确费用结算，只避免不受控重复请求；
- 不自动爬取未知供应商文档或猜测模型能力；
- 不在本阶段实现账号体系、桌宠行为或插件市场。

## 3. 方案选择

采用“Electron 加密配置保险库 + 后端内存路由器”。

- Electron 负责密钥的加密持久化、受信 IPC、候选配置事务和启动引导；
- 后端 `ModelRuntimeRouter` 负责配置选择、连接池、重试、熔断、供应商适配和运行指标；
- Vue renderer 只操作脱敏元数据与选择偏好；
- 配置快照只通过主进程持有的桌面令牌在本机内存中传递。

不采用“每次切换重启后端”，因为会中断流式任务并增加切换延迟；不采用“Electron 直接路由模型请求”，因为会把业务协议、SSE、重试和模型差异堆入主进程，破坏现有边界。

## 4. 组件边界

### 4.1 Electron `ModelProfileVault`

把现有单配置 `model-settings.enc` 升级为版本 2 的 `model-profiles.enc`。保险库保存：

```text
version: 2
global:
  default_profile_id
  auto_failover
  fallback_profile_ids[]
profiles[]:
  id
  label
  enabled
  provider
  base_url
  api_key
  anthropic_version
  request_timeout_seconds
  default_model_id
  models[]
```

每个模型条目保存稳定 ID、供应商模型名、显示名、能力声明、允许的推理档位和供应商适配方式。适配方式必须来自代码内白名单枚举，界面不能保存或发送任意 JSON 参数。保险库整体由 `safeStorage` 加密，继续使用临时文件 + 原子重命名。版本 1 自动迁移为一个启用的默认配置，原密钥不经过 renderer。

保险库不保存运行期成功率、熔断计时器或原始错误；这些状态只存在于后端内存。

### 4.2 Electron `ModelProfileController`

主进程提供固定 IPC 方法：

- 列出脱敏配置与全局策略；
- 测试候选配置；
- 新增或更新配置；
- 删除、启用、停用配置；
- 设置默认配置和备用顺序；
- 更新全局自动故障转移开关；
- 获取后端运行状态。

所有输入先经过字段白名单、长度、URL、枚举和 ID 校验。完整密钥只在受信 renderer 提交候选配置时短暂进入主进程，绝不在 IPC 响应中返回。

配置事务顺序固定为：

1. 解析并补全候选配置；
2. 调用后端临时测试接口；
3. 取得保险库旧快照；
4. 原子保存新保险库；
5. 向后端原子应用新配置快照；
6. 验证 runtime ready；
7. 任一步失败时恢复旧保险库和旧运行快照。

### 4.3 后端 `ModelRuntimeRouter`

路由器持有不可变的 `RuntimeSnapshot`。每次更新先完整构建候选快照，校验通过后用单次引用替换激活；正在运行的请求继续使用旧快照，新请求使用新快照。旧客户端在引用归零后关闭，避免切换时中断已有请求。

快照包含：

- 配置元数据与内存密钥；
- 每个配置独立的 OpenAI/Anthropic 客户端；
- 每个配置的熔断器；
- 模型能力适配器；
- 默认配置和备用顺序；
- 全局自动故障转移策略。

客户端显式 `trust_env=False`，按配置复用连接池。路由器统一管理重试，因此供应商 SDK 的隐式重试应关闭或纳入同一尝试预算，不能发生“SDK 重试 × 路由器重试”的乘法放大。

### 4.4 学习空间偏好

SQLite 新增 `session_model_preferences`：

```text
session_id (PK/FK)
profile_mode: auto | manual
preferred_profile_id: nullable
model_id: nullable
reasoning_effort: auto | off | low | medium | high | xhigh
failover_override: inherit | on | off
updated_at
```

新学习空间继承全局默认；已有学习空间没有记录时也按继承处理。偏好只保存配置 ID 和模型 ID，不保存 Key。配置被删除或停用时，偏好保留但运行时回退全局默认，并向界面显示“原配置不可用”。

## 5. 配置选择与故障转移

### 5.1 候选顺序

1. 学习空间手动选择的首选配置；
2. 全局默认配置；
3. 用户排序后的启用备用配置；
4. 已熔断、停用或能力不匹配的配置被跳过。

手动模式仍可继承全局“允许自动备用”开关；用户也可为单个学习空间显式关闭自动切换。系统不做随机、轮询或基于费用的自动选择。

### 5.2 错误分类

允许自动故障转移：

- DNS、TCP、TLS 和连接中断；
- 请求超时；
- HTTP 408、429、502、503、504；
- 供应商明确标记为临时不可用的错误。

禁止自动故障转移：

- 400/422 参数或协议错误；
- 401/403 认证与权限错误；
- 404 模型不存在；
- 内容安全拒绝；
- 本地输入校验、会话归属或取消错误。

禁止切换的错误必须直接展示，避免用备用配置掩盖错误配置或产生额外费用。

### 5.3 尝试预算

- 每个业务请求共享一个总截止时间，默认来自配置超时但不按配置重新计时；
- 默认最多尝试 3 次、最多涉及 2 套配置；
- 连接建立前失败可在同配置执行 1 次带随机抖动的短重试；
- 429 优先遵循 `Retry-After`；超过剩余截止时间时立即尝试备用配置或失败；
- 一旦收到上游有效响应字节，不再自动重放请求；
- 取消信号必须穿透当前尝试、退避等待和备用尝试。

### 5.4 流式边界

遵循用户已确认的规则：

- 尚未向 renderer 发出任何内容：允许自动切换备用配置并重新建立流；
- 已经发出内容：保留已有文本，发送结构化 `interrupted` 事件，不静默拼接另一个模型的结果；
- 界面提供“使用备用配置继续”，新请求显式携带已有内容摘要与来源模型信息；
- 持久化时标记不完整消息、实际配置、模型和中断原因。

## 6. 熔断与健康状态

每套配置独立维护：

- `closed`：正常接收请求；
- `open`：暂时跳过；
- `half_open`：只允许一个探测请求。

默认策略：60 秒窗口内连续 3 次可重试失败后打开 30 秒；再次失败按 60、120、240 秒递增，最高 5 分钟；成功一次即关闭并清零连续失败。429 按 `Retry-After` 设置冷却，不伪造高频探测。

认证错误不进入普通熔断，而是标记 `needs_attention`。用户修正并测试成功后才恢复。应用不发送周期性付费聊天来“保活”；仅在用户打开设置页或主动刷新时调用免费/低成本模型列表或测试接口，且模型列表失败不影响手动配置。

运行状态只记录：安全错误码、最近成功时间、最近失败时间、EWMA 延迟、连续失败数、熔断状态和冷却结束时间。日志不得包含 Key、请求正文、模型回复或完整配置对象。

## 7. 模型能力与推理强度

统一推理档位：

- `auto`：使用模型或配置默认值；
- `off`：关闭显式推理参数；
- `low`：快速；
- `medium`：标准；
- `high`：深入；
- `xhigh`：极高。

每个模型声明 `supported_reasoning_efforts` 和 `reasoning_adapter`。适配器只使用经过验证的供应商参数：

- OpenAI 兼容模型可映射到 `reasoning_effort` 或供应商明确支持的兼容字段；
- Anthropic 模型可映射到受支持的 thinking/budget 结构；
- 普通模型使用 `none` 适配器，不发送推理字段；
- 自定义网关默认能力为未知，用户可在高级设置中声明，系统不得靠模型名称猜测。

若选择档位不受当前模型支持：

1. 切换前在 UI 中禁用该档位；
2. 运行时仍遇到不兼容时，降到最近的较低受支持档位；
3. 仅在尚未产生输出时允许一次受控降级重试；
4. 响应元数据返回 `requested_reasoning_effort` 与 `effective_reasoning_effort`，界面明确显示实际生效值。

不同配置间故障转移时，优先寻找同一模型 ID；不存在时使用备用配置默认模型。实际使用的配置、模型和推理档位必须进入普通响应元数据和 SSE `meta` 事件，但不改变现有学习协议正文。

## 8. 内部接口与兼容层

新增只允许 Electron 主进程调用的内部接口：

- `POST /internal/model-runtime/bootstrap`：启动时注入完整快照；
- `POST /internal/model-runtime/test`：不持久化测试候选配置；
- `PUT /internal/model-runtime/snapshot`：原子应用新快照；
- `GET /internal/model-runtime/status`：返回脱敏运行状态。

接口必须要求桌面令牌、仅允许 loopback、限制请求体大小、拒绝多余字段，错误继续使用统一错误信封。Electron 主进程直接调用这些接口；renderer 的普通 HTTP 代理白名单不能访问 `/internal/*`。

现有 `/api/settings/model` 在迁移期继续返回全局默认配置的脱敏视图，以兼容现有前端和测试；旧 PUT/测试入口内部转接新路由器，完成 Vue 改造后再标记弃用，不在本阶段直接删除。

业务聊天请求新增可选的脱敏选择字段或由 `session_id` 查偏好；renderer 不得提交 base URL、Key 或任意供应商参数。

## 9. 桌面交互

### 9.1 模型设置页

- 左侧显示配置卡片：名称、供应商、默认模型、最近延迟、健康状态；
- 支持新增、复制、编辑、删除、启停、测试和拖动备用顺序；
- 星标设置全局默认配置；
- 顶部提供“自动使用备用配置”总开关；
- 高级区配置模型列表、推理能力、超时和供应商适配器；
- 编辑 Key 时留空表示沿用原密钥，保存后立即清空输入框。

### 9.2 学习助手选择器

参考用户截图，在输入区附近提供紧凑选择器：

- 主标签显示“模型名称 + 推理强度”；
- 弹层第一行选择配置/模型，第二行选择推理强度；
- 默认展示当前学习空间设置，并提供“跟随全局”；
- 自动切换后显示非打断式提示，例如“主服务暂时不可用，已切换至备用配置”；
- 流式中断时显示保留内容和“使用备用配置继续”按钮。

设置页承担复杂编辑，聊天页只承担高频选择，避免把密钥与高级参数带入学习主流程。

## 10. 错误语义

新增稳定错误码：

- `MODEL_PROFILE_NOT_FOUND`
- `MODEL_PROFILE_DISABLED`
- `MODEL_PROFILE_NEEDS_ATTENTION`
- `MODEL_CAPABILITY_UNSUPPORTED`
- `MODEL_FAILOVER_EXHAUSTED`
- `MODEL_RUNTIME_SNAPSHOT_INVALID`
- `MODEL_RUNTIME_APPLY_FAILED`
- `MODEL_STREAM_INTERRUPTED`

错误信封可附带脱敏字段：`profile_id`、`model_id`、`attempt_count`、`failover_used`、`retry_after`。禁止包含 URL 查询密钥、Key、请求正文和上游原始响应体。

## 11. 并发与生命周期

- 快照更新使用异步写锁，请求读取快照不持有全局长锁；
- 每个学习空间仍保留现有生成锁和取消归属；
- 熔断器的 half-open 探测必须单飞；
- 同配置客户端共享连接池，不同配置不共享认证状态；
- 删除配置时先从新快照移除，旧客户端等待活动请求结束后关闭；
- 应用退出时关闭全部客户端、取消退避任务并清空内存密钥引用。

## 12. 测试与验收门槛

### 12.1 Electron

- 版本 1 到版本 2 的无损迁移；
- 多配置密文不包含 Key 明文；
- 原子保存、恢复和损坏保险库错误；
- IPC 字段白名单、受信 sender 和密钥不回传；
- 配置测试、保存、后端应用失败时完整回滚；
- renderer/preload/构建产物密钥特征扫描。

### 12.2 后端单元测试

- 候选顺序和学习空间覆盖；
- 可重试/不可重试错误分类；
- 总尝试预算、总截止时间、抖动和取消；
- 熔断 closed/open/half-open，使用假时钟；
- 零输出流自动切换、已输出流中断；
- OpenAI、Anthropic 和无推理适配器；
- 档位降级与实际元数据；
- 快照原子替换和旧客户端延迟关闭；
- 日志和错误信封脱敏。

### 12.3 集成与桌面验收

- 使用假网关覆盖超时、429、503、401、404、半流断开和恢复；
- 主配置失败、备用成功时普通请求和零输出 SSE 自动恢复；
- 已输出 SSE 不拼接备用模型文本；
- 切换配置不重启 Electron，不中断旧快照上的活动请求；
- 新安装、旧配置迁移、后端重启和应用重启均能恢复默认配置；
- 真实 API 烟雾测试至少 5 次连续成功，记录 P50/P95，但不以外部网络绝对延迟作为单元门槛；
- 本地配置热应用目标小于 500 ms，不包含外部 API 测试耗时；
- 完整 pytest、Electron Node、Vitest、桌面构建和打包启动检查通过。

## 13. 实施顺序与回滚

1. 先实现后端纯内存路由器、适配器、重试和熔断测试；
2. 再实现 Electron 版本 2 保险库与内部快照通道；
3. 保留旧单配置兼容入口，完成启动迁移和回滚；
4. 实现配置管理 UI；
5. 实现学习空间模型/推理选择器和 SSE 元数据；
6. 完成假网关故障注入、真实桌面测试和打包验证；
7. 稳定后才弃用旧接口。

任何阶段出现问题都可回到版本 1 单配置：保险库迁移前保留内存快照，旧配置接口在 T-033 完成前不删除。不得以清空用户配置作为回滚手段。

## 14. 已确定决策

- 稳定性优先于极限低延迟；
- 手动指定主配置，自动备用切换可全局或按学习空间关闭；
- 全局默认 + 学习空间覆盖；
- 自动切换只处理可重试错误；
- 流式已输出内容后不静默换模型；
- 采用 Electron 加密保险库 + 后端内存路由器；
- 模型能力必须声明或验证，不按名称猜测；
- 配置热应用、原子回滚、客户端复用和脱敏观测为发布硬门槛。

# S-033 离线中文 OCR 与教材页码引用设计

## 目标

让扫描型中文数学教材在完全离线的桌面环境中完成逐页识别、公式字符保留、失败页重试、可恢复导入和准确页码引用，并能从 AI 引用直接跳转到本地 PDF 对应页。

## 方案选择

采用 RapidOCR 的 ONNX Runtime 后端作为默认离线中文 OCR 引擎，保留现有可选包 SHA-256 与兼容版本校验。相比调用系统 OCR，它跨 Windows 版本更稳定；相比 PaddleOCR 完整运行时，它更适合 PyInstaller 与比赛安装包。数学公式不承诺通用 LaTeX 重建，而是优先保留数字、拉丁字母、希腊字母、运算符、上下标近似和行结构，并通过公式规范化器输出可检索文本。

## 架构

- `backend/knowledge/ocr_engine.py` 封装 RapidOCR 延迟加载、模型目录选择、结果排序和公式字符规范化，不接触网络。
- `backend/knowledge/ocr.py` 负责 PDF 渲染、逐页超时、检查点、失败页隔离和 ETA 计算；每页成功立即产生 `BlockEvent`。
- `backend/knowledge/worker_main.py` 在普通解析返回 `ocr_required` 且 OCR 可用时切换 OCR 流程；不可用时仍返回 `OCR_REQUIRED`。
- `KnowledgeImportJob` 保存当前页、总页数、失败页、已耗时与 ETA；重试只处理失败页或未完成页。
- 引用继续使用 `locator_type=page`、一页一个块的真实 PDF 页序号，不根据印刷页脚猜测页码。
- Electron 只负责准备经过校验的本地 OCR 目录、启动打包后端和打开 `#page=N` 只读预览，不把模型路径暴露给 renderer。

## 数据流

1. PDF 普通解析发现平均每页文本少于阈值。
2. Worker 检查 OCR 能力；不可用则安全停止在 `OCR_REQUIRED`，可用则进入 `OCR_RUNNING`。
3. 每页渲染到受限分辨率，OCR 结果排序并规范化，立即写入 worker block 检查点。
4. 单页失败被记录为失败页，其余页面继续；任务结束时若存在失败页则标记可重试失败并保留成功页。
5. 重试任务读取检查点，只识别失败页和缺失页，成功后统一切块、索引并替换旧索引。
6. 检索结果携带页码定位器，前端点击引用调用受控本地阅读器定位到对应页。

## 错误与安全

- 模型缺失、哈希不符、版本不兼容、页级超时、页级识别失败使用不同稳定错误码。
- 原 PDF、OCR 图片和识别文本不离开设备；worker 环境继续移除 API Key、代理和桌面令牌。
- 最大页数、最大渲染边长、单页超时、总时长和文本总量均受限。
- OCR 失败不得覆盖已有可用索引；完成前使用 staging blocks 原子替换。

## 验收

- 单元测试覆盖中文结果、公式字符、逐页进度、ETA、取消、单页失败继续与失败页重试。
- API/前端覆盖 OCR 状态、失败原因、剩余时间和页码引用跳转。
- 打包 worker 能在无源码环境加载离线引擎。
- 使用扫描型 PDF 进行真实导入，至少验证第一页、中间页和末页引用与预览页一致。

## 自审

范围仅覆盖扫描教材 OCR 与真实 PDF 页序号，不承诺手写体或任意复杂公式的语义级 LaTeX 识别；所有失败分支均有稳定状态和可恢复路径。

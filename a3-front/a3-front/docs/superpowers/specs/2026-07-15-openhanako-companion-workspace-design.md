# A3 陪伴式学习工作台设计

## 背景与目标

A3 当前已经具备真实后端驱动的诊断、画像、资源、练习和复习能力，但界面仍然呈现为传统管理后台：顶部横栏、固定菜单和业务卡片。目标是借鉴 `liliMozi/openhanako` 的桌面工作台逻辑，将应用改造成有温度、人性化、带轻微浪漫主义气质的学习空间。

本次范围只调整前端信息架构与视觉表达，不改变现有 FastAPI、SSE、Electron IPC、模型设置安全流程或账号数据边界。账号体系和桌宠暂不实现，但在布局和模块命名上保留插槽，后续可以无痛加入。

## 设计原则

1. **先陪伴，再管理**：用户打开应用首先看到一句欢迎语、当前学习状态和可立即开始的学习入口，而不是指标表格。
2. **三栏空间**：左栏承载对话/空间列表，中栏承载学习对话和输入，右栏承载书桌、进度、来源和便签等低干扰信息。
3. **暖色低对比**：纸张米白作为主背景，墨色文字，蓝绿色作为学习状态色，琥珀色作为提醒和便签色；边框、阴影和圆角保持克制。
4. **渐进披露**：核心学习动作始终突出，画像、智能体、路径和评估作为可进入的空间，而不是同时挤在首页。
5. **扩展边界明确**：未来账号、桌宠、多个角色和工作空间使用独立数据结构与插槽，不把它们硬编码到学习会话组件。

## 方案选择

### 方案 A：在现有布局上做三栏渐进改造（采用）

保留 Vue Router、Pinia、Element Plus 和现有页面路由；重做 `AppLayout` 的壳与 `SmartTutor` 的欢迎态，新增可复用的空间导航、书桌卡片和便签组件。优点是风险最低、接口零改动、可直接复用已有测试和 Electron 壳；缺点是旧页面仍需逐步换肤。

### 方案 B：为首页建立全新独立工作台路由

新增 `/workspace`，将原有页面作为后台子应用。视觉自由度最高，但会产生重复导航和状态同步，且需要迁移默认入口，回归成本较高。

### 方案 C：引入新的 UI 组件库重写

可以获得更完整的设计系统，但会扩大依赖、破坏 Element Plus 按需加载收益，也不利于桌面打包稳定性。

采用方案 A：先让 `/tutor` 成为工作台的情绪中心，再让 `/dashboard` 作为轻量学习摘要；其他路由沿用导航但共享新壳样式。

## 页面与组件结构

### AppLayout 工作台壳

- 顶部仅保留品牌、当前空间名称、服务状态和窗口操作友好的拖拽区域。
- 左侧 `conversation-rail`：新对话按钮、当前学习会话、最近资源/复习/资料入口，以及未来账号入口插槽。
- 中间 `main-content`：路由页面；在 `/tutor` 下使用欢迎式学习对话。
- 右侧 `desk-panel`：可折叠的书桌区域，显示今日学习状态、下一步建议、最近来源和便签。桌宠未来作为同一面板的可选 slot，不与业务逻辑耦合。
- 窄屏时收起左右栏，保留顶部菜单和一个可打开的抽屉；中栏保持输入框和核心行动。

### SmartTutor 欢迎式对话

- 无消息时展示温和欢迎语、当前日期/学习阶段和三个示例目标。
- 角色选择先使用“学习伙伴”静态身份，不实现账号或桌宠；数据结构预留 `companionId`。
- 输入框采用悬浮纸张效果，保留流式开关、取消、错误重试和真实 SSE。
- 已有消息、阶段、来源和错误状态全部沿用当前 API 与 Pinia 状态。

### DeskPanel 信息面板

- `今日书桌`：会话阶段、掌握度、今日练习数。
- `下一步`：使用 `backend.nextAction`，点击后把建议填入对话编辑器。
- `便签`：本地 UI 状态，允许编辑一句短提醒；不写入后端，未来可替换为账号/桌宠持久化。
- `来源`：复用 SSE/普通响应中的来源快照。

## 数据流与边界

```text
Pinia backend store ── refreshAll/refreshSession ── FastAPI / Electron proxy
        │
        ├─ AppLayout：服务状态、会话标题、阶段摘要
        ├─ SmartTutor：消息、SSE、取消、错误恢复
        └─ DeskPanel：下一步、掌握度、来源、便签（本地）
```

所有后端数据仍通过 `src/api` 和 `src/stores/backend.ts` 获取；组件不直接读取桌面令牌、动态端口或模型密钥。便签属于纯前端展示状态，默认只存 `localStorage` 的短文本并限制长度，不影响会话协议。

## 错误与空状态

- 后端离线：顶部显示低干扰离线标记，主区域给出“重新连接”行动，不渲染地址或令牌。
- 模型未配置：继续使用现有自动跳转到模型设置逻辑。
- 无会话：欢迎态替代空白页面，提供可点击示例目标。
- SSE 失败：保留当前错误条、失败消息和重新编辑动作，只调整视觉层级。
- 右栏无数据：显示短句式空状态，例如“今天的书桌还很安静”。

## 验收标准

1. `/tutor` 首屏具备三栏工作台逻辑：左侧空间导航、中间欢迎/对话、右侧书桌信息。
2. 发送、流式输出、取消、失败重试、来源展示与现有 Vitest 行为测试继续通过。
3. `/dashboard`、`/profile`、`/agents`、`/learning-path`、`/assessment`、`/model-settings` 在新壳下可访问，现有接口行为不回退。
4. 375px 窄屏无横向滚动，导航和书桌面板可折叠，输入框可用。
5. `npm run test`、`npm run build`、`npm run build:desktop` 全部通过。
6. 代码中不引入账号登录、桌宠运行时或新的后端接口；为未来能力保留 `companionId`、`accountSlot` 和 `desktopWidgetSlot` 的前端扩展位置。

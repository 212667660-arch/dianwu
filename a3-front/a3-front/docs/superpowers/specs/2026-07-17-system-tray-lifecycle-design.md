# 智学协作台系统托盘与退出生命周期设计

> 状态：用户已通过“全部采用推荐方案、无需再次确认”授权实施
> 适用范围：Windows Electron 桌面端主窗口、系统托盘、桌宠窗口与后端进程

## 1. 问题与根因

当前 Electron 主进程没有导入或创建 `Tray`，因此 Windows 通知区域不会出现“智学协作台”。应用同时拥有主窗口和桌宠窗口；主窗口被关闭或隐藏后，辅助窗口与后端仍可能维持主进程，用户却没有托盘入口恢复主窗口或执行完整退出。

## 2. 目标行为

1. 应用启动成功后创建唯一系统托盘图标，提示文字为“智学协作台”。
2. 单击或双击托盘图标时，恢复、显示并聚焦主窗口。
3. 托盘右键菜单只提供“打开智学协作台”和“退出智学协作台”两个稳定操作。
4. 用户点击主窗口关闭按钮时，主窗口隐藏到托盘，后端和桌宠按原状态继续工作。
5. 用户选择托盘“退出智学协作台”时，设置退出状态并调用 `app.quit()`；既有 `before-quit` 负责关闭桌宠、知识任务、流式代理和后端。
6. 如果托盘创建失败，关闭主窗口必须退化为完整退出，不能留下无入口的后台进程。
7. 第二次启动应用时，恢复已有实例的主窗口，不创建第二套后端或托盘。

## 3. 方案比较

- 仅创建托盘，主窗口关闭仍直接退出：改动小，但托盘只在窗口可见时存在，恢复功能价值很低。
- 不创建托盘，只增加窗口内退出按钮：不能满足用户在 Windows 右下角寻找应用和退出的习惯。
- 关闭隐藏到托盘、托盘提供完整退出：符合常见后台应用行为，也能让桌宠和长任务在主窗口隐藏时继续运行。采用此方案。

## 4. 组件边界

### `electron/tray-lifecycle.mjs`

提供可用纯 Node 假对象测试的托盘控制器：创建托盘、构造菜单、显示主窗口、处理退出请求和销毁托盘。该模块不读取模型配置、后端令牌或渲染器数据。

### `electron/main.mjs`

只负责把 Electron 的 `Tray`、`Menu`、`nativeImage`、当前主窗口和 `app.quit()` 注入托盘控制器；主窗口 `close` 事件依据 `isQuitting` 与托盘可用状态选择隐藏或退出。`before-quit` 继续作为全部运行时资源的统一清理入口。

### `electron/assets/tray-icon.png`

从仓库已有“墨团”本地素材派生 32×32 透明 PNG，不引入网络资源或第三方版权素材。Electron 打包规则中的 `electron/**` 会自动包含该文件。

## 5. 状态流

```text
启动成功
  -> 创建主窗口、桌宠与托盘
  -> 点击主窗口关闭
     -> 托盘存在：阻止关闭并隐藏主窗口
     -> 托盘缺失：进入 app.quit()
  -> 点击托盘：恢复/显示/聚焦主窗口
  -> 点击托盘退出：isQuitting=true -> app.quit()
     -> before-quit -> 停止后端、桌宠与知识任务
     -> 所有进程退出
```

## 6. 错误与安全边界

- 空托盘图像视为创建失败并记录安全日志，不允许显示一个不可见托盘入口。
- 托盘菜单不经过 renderer IPC，不暴露桌面令牌、后端地址或文件路径。
- 退出操作只调用既有主进程清理路径，不使用 renderer 强制结束进程。
- `A3_ELECTRON_TEST_MODE` 仍可在页面加载后执行受控退出，且托盘会在退出时销毁。

## 7. 验收

- 单元测试证明托盘单击会恢复窗口、菜单退出只调用退出请求、销毁幂等。
- 单元测试证明普通关闭在托盘存在时隐藏，在退出中或托盘缺失时不隐藏。
- Electron 全量 Node 测试、Vitest、`build:desktop` 和 `desktop:pack` 通过。
- 最新 unpacked 包测试模式日志包含 `tray ready`、后端 ready/stop 与强制退出，退出码为 0，残留进程为 0。

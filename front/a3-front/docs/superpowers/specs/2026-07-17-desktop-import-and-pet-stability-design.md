# 桌面端文件导入与墨团交互稳定性设计

> 状态：设计已获用户预先批准，进入实施计划阶段
> 范围：Electron 桌面端、知识库文件导入、文件预览与墨团交互

## 1. 目标与已确认根因

本规格解决两个可复现问题：连续点击墨团后视觉尺寸持续变化，以及教材文件无法导入。

文件导入失败已经用 `C:\Users\123\Desktop\作业\教材` 中的真实 PDF 复现。77 MB 文件可以导入，约 188 MB 文件被 `KNOWLEDGE_FILE_TOO_LARGE` 拒绝；中文路径、中文文件名和 PDF 文件签名均正常，根因是 Electron 与 FastAPI 同时把单文件上限固定为 100 MiB。

墨团窗口持久化设置始终为 192×208、缩放为 1，BrowserWindow 也不可调整大小，因此当前证据不支持“窗口尺寸被每次点击永久放大”。更可能的根因位于渲染层：连续交互触发的动作计时器、DPR backing store 或画布清理没有形成幂等生命周期，导致视觉帧或变换累积。实施前必须用失败测试和运行时尺寸记录锁定具体边界。

## 2. 方案比较与选择

### 方案 A：只提高文件上限并限制点击频率

改动最小，但点击节流只能掩盖墨团状态重入，且大 PDF 的解析超时、进度和预览仍不可靠。不采用。

### 方案 B：重写整个上传与桌宠渲染模块

可以彻底替换现有结构，但风险和回归面过大，也会丢失当前已经完成的流式复制、哈希去重、隔离解析和角色包能力。不采用。

### 方案 C：保留现有安全边界，修复限制和交互生命周期

采用此方案。文件继续由 Electron 主进程流式复制到知识对象存储，后端继续隔离解析；只把单文件上限提高到 500 MiB，并补齐大文件进度、超时与预览入口。墨团保持固定逻辑画布和窗口尺寸，将点击动作变成可取消、不可叠加的单一交互状态。

## 3. 文件位置与运行数据边界

Git 跟踪文件审计结果为 345 个，全部位于 `E:\软件杯` 之内，没有项目源文件写到工作区之外。

允许存在的外部数据只有桌面应用正常运行所需内容：

- Electron `userData` 中的数据库、加密模型配置、知识对象、桌宠设置和日志；
- Windows 临时目录中的解析或预览临时副本；
- 用户主动选择的原始文件，例如 `C:\Users\123\Desktop\作业\教材`。

外部文件不被移动或修改；导入创建受控副本。所有新增源码、测试、规格和计划必须继续写在 `E:\软件杯` 内。

## 4. 墨团交互设计

### 4.1 固定尺寸不变量

- 逻辑画布固定为 192×208；角色帧只在该坐标系内绘制。
- CSS 可视尺寸和 BrowserWindow bounds 不因单击、双击、拖动开始或动作切换而变化。
- backing store 只在 `devicePixelRatio` 或固定逻辑尺寸变化时重建，尺寸为逻辑尺寸乘 DPR。
- 每帧绘制前重置变换并清空完整 backing store，不能在上一帧的变换上继续缩放。

### 4.2 幂等交互状态

- 同一时刻最多存在一个点击动作计时器；新动作先取消旧计时器。
- 单击触发挥手，双击触发跳跃，但双击判定不得叠加两个单击动作。
- 动作结束统一回到 idle，不修改持久化 `scale`、窗口位置宽高或 canvas CSS 尺寸。
- 拖动只改变窗口坐标，不把位移或点击次数写入角色缩放。

### 4.3 诊断与测试

单元测试连续触发 100 次单击、50 次双击和单/双击混合序列，断言活动计时器最多一个、最终回到 idle、逻辑尺寸和窗口设置不变。Electron 运行时验收记录点击前后的窗口 bounds、DPR、canvas bitmap 尺寸和 client 尺寸，以区分窗口变化与纯视觉变化。

## 5. 500 MiB 文件导入设计

### 5.1 限额

- 单文件最大 500 MiB。
- 单次批量导入总量最大 500 MiB。
- 限额在 Electron 选择/复制边界和 FastAPI 请求模型中保持一致。
- 错误文案同时显示实际文件大小和 500 MiB 上限。

用户目录中的两个 PDF 合计约 253 MiB，因此应能在同一批次导入。

### 5.2 数据流

```text
用户选择文件
  -> Electron 校验路径、扩展名、签名、单文件/批次大小
  -> 流式复制并计算 SHA-256
  -> 原子写入 userData 知识对象存储
  -> FastAPI 创建文档记录
  -> 隔离 worker 按页解析
  -> 切片、索引、可检索状态
```

实现不得把整个 500 MiB 文件读入 renderer 或 Python 主进程内存。大 PDF 继续按页处理，解析超时按照文件大小和页数提高，并通过已有任务状态显示“复制、解析、索引、完成/失败”。失败保留稳定错误码和可重试入口，不留下半成品对象。

## 6. 预览与外部阅读器

首选体验是知识库卡片提供两个明确入口：

- “预览”：PDF 和可解析文本显示安全的页级/文本预览；预览失败时显示原因并保留外部打开入口。
- “用本地阅读器打开”：主进程把知识对象复制到独立只读预览目录，再调用系统默认应用打开；不直接把可写对象存储路径暴露给 renderer。

PDF 首版预览复用解析后的页级文本、页码和缩放控制；若当前打包环境无法稳定内嵌某类格式，则自动降级为系统默认阅读器。原始用户文件删除后，已导入的受控副本仍可预览。

## 7. 错误处理与安全

- 非普通文件、路径穿越、扩展名与签名不一致、超限和复制中断在入库前拒绝。
- 对象文件名使用内部 UUID/哈希，不信任用户文件名构造目标路径。
- 预览副本只读、按任务隔离，并允许应用启动时清理过期副本。
- 解析 worker 的内存、时间和输出长度继续受限；单个失败文件不阻塞同批其他文件。
- 日志记录阶段、大小、耗时和稳定错误码，不记录教材正文、模型密钥或用户隐私文本。

## 8. 验收标准

1. 连续点击和双击墨团不会改变窗口、canvas 或持久化缩放，视觉尺寸稳定。
2. 用户目录中的 77 MB 与 188 MB PDF 可以分别导入，也可在同一约 253 MiB 批次导入。
3. 500 MiB 边界值被接受，超过一个字节被 Electron 和后端一致拒绝。
4. 大文件导入有可见进度、合理超时和明确失败重试。
5. 导入文件可以应用内预览或用系统默认阅读器打开只读副本。
6. Electron/Node、前端、后端和打包回归全部通过，最新 unpacked 桌面端可双击运行。

## 9. 规格自审

- 所有数值和行为均已确定；单文件与批次均明确为 500 MiB。
- 墨团问题先通过尺寸证据和失败测试定根因，不把节流当作最终修复。
- 文件预览与外部打开均不暴露知识对象可写路径。
- 本规格只覆盖稳定性和本地导入，不混入在线教材版权策略或学习提示词实现。

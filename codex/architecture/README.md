## 已锁定决策

- 产品主流程使用 Coordinator 管理状态，Agent 不直接写数据库。
- 新用户至少经过一次诊断追问，最多五轮后生成画像。
- Agent 边界使用可读纯文本协议，内部用 Pydantic 校验。
- 未校验输出不得进入正式画像和资源表。
- SSE 必须来自模型真实分片，并支持取消、错误和最终确认事件。
- 模型故障通过领域异常传播，不能作为普通学习文本返回。
- session、画像、资源和生成任务必须隔离并带版本或 request_id。
- Electron renderer 不直接持有后端 token 和 API Key，由 main process 代理。
- 数据库、日志和配置写入 Electron userData，不写安装目录。
- 每次模型、提示词或协议修改必须运行对应级别的效果回归。

## Terra 推荐实现顺序

1. T-001 修复依赖和包导入。
2. T-006 建立测试基础，先保护现有行为。
3. T-007、T-008、T-009、T-010 完成生命周期、校验、事务和配置基础。
4. T-002 实现状态机和 Coordinator。
5. T-003 实现协议 models、parser、serializer 和 validator。
6. T-004 实现异常体系和全局错误处理。
7. T-005 实现真实 SSE 与取消。
8. T-011 接入模型效果回归。
9. T-012 增加历史和会话管理接口。

## 维护规则

- 架构变更先修改对应 S 文档，再修改实现和测试。
- 协议字段变化必须遵循 S-002 的版本策略。
- 新的模型错误先归类到 S-004 的异常体系，不添加错误关键词判断。
- 新的安全风险补入 S-006 的威胁和测试集。
- 完成 Terra 任务后在 AI模型任务队列.md 记录修改文件和验证结果。

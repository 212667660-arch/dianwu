# S-004 模型错误语义与降级策略

## 1. 目标

模型故障必须以明确异常和错误事件传播，不能伪装成普通学习文本。调用方能够判断是否重试、是否恢复状态、向用户显示什么，以及哪些信息可以记录。

## 2. 当前问题

- llm_call 捕获所有异常并返回“服务暂时不可用”字符串。
- 业务层通过“尚未配置”“⚠️”等关键词识别失败，存在误判和漏判。
- profile 和 resource 接口捕获所有异常后仍返回 200。
- print 日志缺少 request_id、错误类型和阶段。
- 配置错误、鉴权失败、限流、超时、协议错误和数据库错误没有区分。

## 3. 异常层次

AppError 为统一基类，包含：code、public_message、retryable、http_status、phase、details_safe。

### 配置与请求

- ConfigurationError：缺失密钥、地址或模型名，HTTP 503，不重试。
- RequestValidationError：用户请求字段非法，HTTP 422，不重试。
- DomainStateError：非法会话状态或重复任务，HTTP 409，视情况重试。

### 模型上游

- ModelAuthenticationError：密钥无效，HTTP 503，不重试。
- ModelPermissionError：模型无权限，HTTP 503，不重试。
- ModelRateLimitError：限流，HTTP 429，可重试。
- ModelTimeoutError：连接、首分片或空闲超时，HTTP 504，可重试。
- ModelUnavailableError：网络或上游 5xx，HTTP 503，可重试。
- ModelBadRequestError：模型参数或输入过长，HTTP 502，通常不重试。
- ModelEmptyResponseError：上游成功但无文本，HTTP 502，可有限重试。

### 业务与持久化

- ProtocolValidationError：Agent 输出不符合协议，HTTP 502；允许一次修复，修复失败后不再重试。
- PersistenceError：数据库事务失败，HTTP 500，可在幂等保障下重试。
- ClientCancelledError：客户端取消，HTTP 不返回普通响应；SSE 状态为 cancelled。

## 4. 上游异常映射

ModelGateway 只做 SDK 异常到领域异常的转换：

- APIConnectionError → ModelUnavailableError。
- APITimeoutError → ModelTimeoutError。
- AuthenticationError → ModelAuthenticationError。
- PermissionDeniedError → ModelPermissionError。
- RateLimitError → ModelRateLimitError。
- BadRequestError → ModelBadRequestError。
- InternalServerError 或其他 5xx → ModelUnavailableError。
- 成功响应但 content 为空 → ModelEmptyResponseError。

禁止在 Gateway 中返回错误字符串或直接生成用户文案。

## 5. HTTP 与 SSE 映射

普通 HTTP：

- 返回统一错误体：code、message、retryable、request_id。
- 422 用于用户输入；409 用于状态冲突；429 用于限流；502 用于上游输出非法；503 用于配置、鉴权和不可用；504 用于超时。
- 响应中不返回 Python 异常文本、SDK 请求体、API Key 或完整提示词。

SSE：

- 已建立流后使用 error 事件，不尝试更改 HTTP 状态码。
- error 后必须发送 done，status=failed 或 cancelled。
- 若流尚未开始，可直接返回标准 HTTP 错误。

## 6. 重试策略

| 错误 | 自动重试 | 规则 |
| --- | --- | --- |
| 限流 | 是 | 最多 2 次，尊重 Retry-After |
| 连接失败 | 是 | 最多 2 次，指数退避加随机抖动 |
| 首分片超时 | 是 | 尚未发送 delta 时最多 1 次 |
| 空闲超时 | 否 | 已有部分输出，返回可重试错误 |
| 上游 5xx | 是 | 最多 2 次 |
| 空响应 | 是 | 最多 1 次 |
| 鉴权、权限、错误参数 | 否 | 立即失败并提示检查配置 |
| 协议错误 | 修复一次 | 使用专用修复提示，不重复原任务 |
| 数据库错误 | 有条件 | request_id 幂等时允许重试事务 |

退避建议：0.5 秒、1.5 秒，再加 0 到 300 毫秒抖动。桌面应用总等待时间必须受完整任务超时限制。

## 7. 降级原则

- 不在模型不可用时伪造画像、练习题或答案。
- 保留并允许读取最后一次有效画像和历史资源。
- 诊断中失败时保留已收集消息，用户重试后从原轮次继续。
- 资源生成失败时恢复 PROFILED，允许重新生成。
- 只有显式开启 DEMO_MODE 时才允许使用固定演示样例，并在界面明显标记“演示数据”。
- 配置缺失时 readiness 失败，但 liveness 仍可成功，便于 Electron 判断后端进程是否存活。

## 8. 日志与可观测性

每条日志至少包含：timestamp、level、request_id、session_id_hash、phase、agent、model、latency_ms、error_code、retry_count。

安全要求：

- session_id 记录哈希或截断值。
- 不记录 API Key、Authorization 头和完整用户对话。
- 默认不记录完整提示词和模型输出。
- 调试模式只允许记录脱敏后的摘要，且打包版本关闭。
- 堆栈写入本地受限日志，不返回给前端。

## 9. 健康检查

- GET /health/live：只检查进程和事件循环，始终不调用模型。
- GET /health/ready：检查配置格式、数据库可写和模型客户端可初始化，不执行计费调用。
- 可选 GET /health/model：用户主动触发一次最小模型测试，明确提示可能产生调用费用。

## 10. 配置启动策略

- 开发模式允许无密钥启动，但 readiness 返回未就绪，模型接口返回 ConfigurationError。
- 打包生产模式可启动后进入“等待配置”界面，不让进程崩溃。
- .env 只用于开发；Electron 使用应用数据目录中的安全配置或系统凭据存储。
- 配置变更后重建模型客户端，避免模块导入时永久缓存旧密钥。

## 11. Terra 实现清单

- 新建 errors.py 定义领域异常和错误代码。
- llm_service 改为 ModelGateway，移除错误文本返回。
- 新建 FastAPI 全局异常处理器。
- 为 SSE 增加 error 和 done 事件编码。
- 使用结构化 logging，替换 print。
- 将模型客户端改为按配置生命周期创建，而不是模块导入时创建。
- 增加 liveness、readiness 和可选模型测试接口。
- 为每种异常映射和重试边界编写测试。

## 12. 验收标准

- 模型失败不会被保存为画像或学习资源。
- 普通接口使用正确非 200 状态和稳定错误代码。
- SSE 在失败时发送 error 与 done，前端可判断是否重试。
- 日志能按 request_id 追踪完整流程且不泄露敏感信息。
- 鉴权错误不重试，限流和网络错误按上限重试。
- 任何失败后会话都能回到可恢复状态。

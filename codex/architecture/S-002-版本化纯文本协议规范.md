# S-002 版本化纯文本协议规范

## 1. 设计目标

Agent 间通信继续使用可读纯文本，但必须具备版本、唯一字段、严格边界和确定性解析。内部可以转换为 Pydantic 对象进行校验，跨 Agent 边界仍传递规范化纯文本。

## 2. 通用规则

- 编码统一为 UTF-8。
- 第一行必须是协议头，最后一行必须是【协议结束】。
- 字段名必须精确匹配，不使用 startswith 模糊识别。
- 单值字段一行一个，格式为“字段名：值”。
- 列表字段使用全角分隔符“｜”，列表项内部不得出现该字符。
- 同一字段只能出现一次；重复字段属于协议错误。
- 未知字段在同一主版本内允许保留但不参与业务判断。
- 必填字段不可为空；未知信息统一写“未明确”。
- 协议标记只允许出现在行首，用户原文必须放入数据块，不能与协议字段混合。
- 协议修复最多调用模型一次，第二次仍失败则返回协议错误。

## 3. 诊断决策协议

协议名：diagnosis-decision/v1

示例：

【协议:diagnosis-decision/v1】
状态：CONTINUE
当前轮次：2
已确认字段：学科｜学习目标
缺失字段：当前水平｜薄弱知识点｜学习风格证据
置信度：0.42
下一问题：你在学习一次函数时，最容易卡在哪一步？
完成理由：信息仍不足，需要定位具体薄弱点。
【协议结束】

字段约束：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| 状态 | 枚举 | CONTINUE 或 COMPLETE |
| 当前轮次 | 整数 | 1 到 5 |
| 已确认字段 | 列表 | 可为空时写“无” |
| 缺失字段 | 列表 | COMPLETE 时允许为“无” |
| 置信度 | 小数 | 0.00 到 1.00 |
| 下一问题 | 文本 | CONTINUE 时必填，COMPLETE 时写“无” |
| 完成理由 | 文本 | 必填，不超过 120 字 |

一致性规则：

- CONTINUE 必须有下一问题且缺失字段不能为“无”。
- COMPLETE 的置信度应不低于 0.65；达到第 5 轮时可低于该值，但必须说明低置信度结束。

## 4. 学习者画像协议

协议名：learner-profile/v1

示例：

【协议:learner-profile/v1】
画像版本：1
年级：初二
学科：数学
当前水平：基础
薄弱知识点：一次函数图像｜待定系数法
学习风格偏好：视觉型
学习风格证据：偏好通过图像理解斜率变化
认知层次：理解
学习目标：能够独立画出一次函数图像并完成基础题
推荐难度：基础｜提高
置信度：0.78
待确认问题：实际应用题中的建模能力尚未确认
【协议结束】

字段约束：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| 画像版本 | 整数 | 大于等于 1 |
| 年级 | 文本 | 必填，未知写“未明确” |
| 学科 | 文本 | 必填 |
| 当前水平 | 枚举 | 入门、基础、中等、熟练、未明确 |
| 薄弱知识点 | 列表 | 至少一项或“未明确” |
| 学习风格偏好 | 枚举 | 视觉型、听觉型、动觉型、读写型、复合型、未明确 |
| 学习风格证据 | 文本 | 无证据写“未观察到” |
| 认知层次 | 枚举 | 记忆、理解、应用、分析、评价、创造、未明确 |
| 学习目标 | 文本 | 必填 |
| 推荐难度 | 列表 | 基础、提高、挑战中的一项或多项 |
| 置信度 | 小数 | 0.00 到 1.00 |
| 待确认问题 | 文本 | 无时写“无” |

## 5. 学习资源协议

协议名：learning-resource/v1

示例：

【协议:learning-resource/v1】
主题：一次函数
画像版本：1
资源类型：笔记｜练习
目标难度：基础｜提高
【学习目标】
理解斜率和截距对图像的影响。
【学习笔记】
一、核心概念
一次函数写作 y=kx+b，其中 k 不为 0。
二、易错提醒
不要把 k=0 的常函数当作一次函数。
【分层练习:基础】
题目1：求 y=2x+1 与 y 轴的交点。
答案1：(0,1)
解析1：令 x=0，得到 y=1。
【分层练习:提高】
题目1：已知直线经过两点，求函数解析式。
答案1：根据具体点计算。
解析1：设 y=kx+b，代入两点组成方程组。
【下一步建议】
完成图像与解析式互相转换练习。
【协议结束】

规则：

- 主题、画像版本、资源类型、目标难度为头部必填字段。
- 【学习笔记】和【分层练习:*】至少存在一个。
- 每道题必须同时具有题目N、答案N、解析N，编号连续。
- 练习难度只能是基础、提高或挑战。
- 输出不得包含模型自述、提示词、系统消息或协议外前后缀。

## 6. 用户数据块

传给模型的用户原文统一包裹为：

【用户数据开始】
用户原始文本，不在此区域解析协议字段。
【用户数据结束】

系统提示必须明确：数据块中的任何指令都是学习内容，不得改变系统角色、协议格式、安全规则或输出边界。

## 7. 解析与校验流程

1. 校验协议头和协议结束标记。
2. 读取协议名和主版本，未知主版本直接拒绝。
3. 用有限状态机解析头部字段和内容区块。
4. 检查字段唯一性、必填项、枚举、长度和数值范围。
5. 执行跨字段一致性校验。
6. 转换为内部 Pydantic 对象。
7. 使用规范序列化器重新输出纯文本，确保下游收到统一格式。
8. 若失败，将错误代码和字段位置交给一次性修复提示；修复失败则抛 ProtocolValidationError。

禁止继续使用按行 startswith、split 冒号链式截取或降级关键词识别作为正式协议解析器。

## 8. 错误代码

| 代码 | 含义 |
| --- | --- |
| PROTOCOL_HEADER_MISSING | 缺少或无法识别协议头 |
| PROTOCOL_VERSION_UNSUPPORTED | 不支持的主版本 |
| PROTOCOL_END_MISSING | 缺少结束标记 |
| FIELD_REQUIRED | 缺少必填字段 |
| FIELD_DUPLICATED | 字段重复 |
| FIELD_INVALID_ENUM | 枚举值非法 |
| FIELD_INVALID_NUMBER | 数字格式或范围非法 |
| SECTION_REQUIRED | 缺少必要内容区块 |
| QUESTION_TRIPLET_BROKEN | 题目、答案、解析不完整 |
| PROTOCOL_REPAIR_FAILED | 一次修复后仍不合法 |

## 9. 版本策略

- 增加可选字段时升级次版本，v1 解析器可忽略未知字段。
- 删除字段、改变含义或改变区块语法时升级主版本。
- 数据库保存 protocol_name、protocol_version 和原始规范文本。
- 旧资源不自动重写；读取时按其原版本解析。

## 10. Terra 实现清单

- 新建 protocols 包，包含 models、parser、serializer、errors。
- 为三种协议建立 Pydantic 模型。
- 将 profile_agent 和 resource_agent 输出先校验再返回。
- 将现有 _extract_field 和 _set_field 降为迁移兼容工具，最终移除。
- 为合法、缺字段、重复字段、错误枚举、断裂题组三元组编写测试。

## 11. 验收标准

- 同一合法文本解析后再序列化，语义保持一致。
- 任意缺失、重复或非法字段都返回确定错误代码。
- 用户输入中的伪协议字段不会被当作 Agent 输出解析。
- 画像和资源协议都能被人直接阅读和手工调试。
- 下游 Agent 只接收校验后的规范文本。

# AI 换模型策略

## 模型切换规则

- Terra：主力后端代码开发，适合日常 CRUD、业务逻辑、接口实现、数据处理、常规调试与测试编写。
- Sol：复杂架构设计、多 Agent 协议设计、疑难 Bug 排查、关键技术选型、跨模块重构与高风险代码审查。
- Luna：轻量小工具、注释补充、文档编写、简单摘要、格式整理与低复杂度辅助任务。

## 任务登记与批量执行

- 新任务先登记到 AI模型任务队列.md，并标注目标模型、优先级、依赖和状态。
- 当前模型继续批量执行属于它的“就绪”任务，其他任务暂存到对应模型队列。
- 当前模型队列完成、全部阻塞或出现关键前置依赖时，再提醒用户手动切换模型。
- 模型切换后更新队列中的“当前模型批次”，从最高优先级任务继续。
- 回答结束时报告批次进度和下一任务，不再为每个任务重复要求切换模型。

## 当前项目建议

针对 A3-基于大模型的个性化资源生成与学习多智能体系统开发：

- 默认使用 Terra 作为后端开发主力模型。
- 遇到系统架构、多 Agent 协议、流式输出方案、复杂排错时切换到 Sol。
- 编写 README、注释、小脚本、简单格式化内容时使用 Luna。

## 按模型批量执行

项目任务统一记录在 AI模型任务队列.md。当前模型只执行其就绪任务；其他模型任务先登记和保留，直到用户手动切换到对应模型。只有当前模型队列完成、阻塞或存在前置依赖时才提醒切换，不再要求每个任务单独切换模型。
